# 提示词库

四个提示词，分别对应「生成 → 改造 → 写脚本 → 自检」。复制就能用，把方括号里的内容换成你的。

## A. 从零生成一套演示（给会写代码的 AI）

> 适用：没有模板、想从零做一个机械产品的交互演示。DeepSeek Harness / Claude Code / Cursor 都可以。

```text
做一个「[产品名]」的可交互 3D 销售演示，单文件 HTML，用 three.js，给客户现场演示用。

产品事实（不要编）：
- 结构：[例如：双转子，偏心轴，8 字缸体]
- 关键参数：[功率/转速/扭矩/重量/尺寸]
- 三个和竞品的结构差异：[……]

页面结构：
- 左侧 3D，右侧参数栏（大号衬线数字），底部一排状态按钮；
- 参数栏：油门/负载滑块 0–100%，联动转速、扭矩、功率，功率必须用 P = T·2πn/60 实时算；
- 五个状态：合上、切开（移开前盖露出剖面）、拆开（沿主轴散开）、透视（外壳半透明）、故障（[最常见的失效模式]）。

交互要求：
- 鼠标拖动旋转、滚轮缩放；
- 每个按钮用快捷键，并且在点下去时弹出一句话术（销售照着念的那句）；
- 故障要能恢复。

视觉：
- 暖白纸面、灰色金属、细黑描边、衬线大数字，像工程剖视图；
- 不要游戏风、不要霓虹色、不要粒子特效。

做完自己截图检查：结构是否闭合、数字是否合理、五个状态是否都能用。检查两轮再给我。
```

## B. 在模板上改（最快，推荐）

> 适用：已经 clone 了这个仓库。改一个文件就能换产品。

```text
这个项目是一个发动机销售演示模板，配置文件在 src/spec.js。

请把它改成 [产品名]：
- 品牌：[品牌名]
- 产品名 / 副标题：[13B] / [双转子平台]
- 几何参数：R = [105] mm，e = [15] mm（如果是别的结构，告诉我需要改哪里）
- 性能：怠速 [875]，全开 [6900] rpm，峰值扭矩 [190] N·m
- 六个标注的文案：[……]
- 四句销售话术：[切开的一句 / 拆开的一句 / 透视的一句 / 故障的一句]

改完运行 python build.py，用 Playwright 截 5 张图（合上、切开、拆开、透视、故障），
检查：顶角贴壁、三腔颜色切换、油门到底的数字是否等于参数表。
```

## C. 写演示脚本（给任何 AI，不需要代码）

> 适用：demo 做好了，需要一份销售能照着念的脚本。

```text
你是工业品销售总监。下面是一套发动机交互演示的五个状态，请写三版演示脚本。

五个状态：合上、切开、拆开、透视、故障。
产品卖点：[三条]。
客户角色：使用、设备、采购、财务、老板。

输出：
1. 30 秒版（展会开场），4 句以内；
2. 3 分钟版，表格：时间 / 动作 / 客户看到 / 我说；
3. 8 分钟版，标出在哪一段回答哪个角色的顾虑；
4. 每个状态配一句「客户最可能问的问题」和一句应答。

要求：口语、短句、不吹牛、不贬低竞品、不出现「颠覆」「赋能」这类词。
```

## D. 自检（让 AI 验收自己的作品）

> 适用：demo 刚生成完，别急着拿去见客户。

```text
用 Playwright 打开 [文件路径]，按下面的清单逐条检查，每条给出「通过 / 不通过 + 截图」。

1. 顶角是否始终贴壁（取 6 个不同转子角度截图）
2. 三个腔的颜色是否随相位切换
3. 油门 0 / 50 / 100 时，转速和功率是否与参数表一致（误差 < 2%）
4. 切开后前盖是否完全让开，剖面是否可见
5. 拆开后零件是否还穿在主轴上
6. 故障状态功率是否下降、密封片是否变色、再点是否恢复
7. 中文是否有错别字，单位是否正确
8. 1600×900 下是否有元素重叠、溢出、被裁切

不通过的项目，直接修，修完重新截图，直到全部通过。
```

## 用提示词的四条经验

1. **把验收标准写进提示词**，不要写「做得好一点」。
2. **给数字，不给形容词**。「6,900 rpm / 109 kW」比「动力强劲」有用一百倍。
3. **要求它自己截图**。看不见结果的 AI 会自我感觉良好。
4. **一次只改一个维度**。同时改结构和配色，出问题你不知道是哪里的错。
